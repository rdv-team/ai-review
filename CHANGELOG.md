# История изменений

Все значимые изменения проекта документируются в этом файле.

## [2.0.0] - 2026-11-27

### Добавлено

- При повторном ревью задачи или Merge Request можно выбрать последний проверенный коммит и проверить только более новые изменения. Выбор доступен в расширении Jira и через `review-tasks init --after-commit`.
- При повторном ревью предыдущий отчёт сохраняется автоматически. В истории отчётов можно открыть его и посмотреть прежние замечания, комментарии и решения.
- В текущем отчёте Jira можно отредактировать предложение к замечанию. При копировании в Jira или Markdown используется сохранённый текст.
- Из отчёта Jira на Windows можно открыть отдельную сессию OpenCode для обсуждения всего отчёта или одного замечания.
- На Stage 2 агент может искать определения и использования и читать нужные участки кода в локальных репозиториях, выбранных при подготовке задачи. Для ранее подготовленных задач повторите `init`.
- Локальный сервис поддерживает OpenCode V2. В логе агента видны выбранная модель, ответы, доступные рассуждения и результаты работы инструментов.

### Изменено

- **Несовместимое изменение:** локальный сервис по умолчанию ожидает OpenCode V2. Чтобы продолжить работу с V1, выполните `review-tasks local-service config --opencode-cli-version v1` и перезапустите сервис.
- **Несовместимое изменение:** память задачи заменяет прежнюю обратную связь. Используйте `review-tasks memory-read --task <TASK>` вместо `read-feedback` и обновите расширение Jira вместе с сервисом. Старые указания и решения по карточкам автоматически не переносятся. Нужные указания можно заново сохранить кнопкой «Сохранить в память».
- Вопросы автору в отчёте Jira можно раскрыть, чтобы увидеть ход проверки, предложение или причину отклонения и перейти к связанному коду в GitLab, если есть ссылка.
- Уточнены правила ревью 1С для запросов к реквизитам составного типа, параметров серверных вызовов и поиска в коллекциях. Обновлены инструкции по проверке BSL и поиску функций БСП через MCP.

### Удалено

- **Несовместимое изменение:** Stage 2 больше не формирует текстовую сводку. В отчёте по-прежнему видны вопросы автору и недостающий контекст.

### Исправлено

- После ошибки предварительной проверки окружения расширение Jira снова предлагает повторить ревью.

## [1.3.0] - 2026-11-05

### Добавлено

- Интерактивный отчёт в расширении Jira: замечания собраны в карточки с рекомендациями и ссылками на код. В отдельном списке можно посмотреть, какие замечания агент отклонил и почему.
- Принятие и отклонение замечаний с комментариями. Решения сохраняются при повторном открытии отчёта, а счётчик показывает, сколько замечаний осталось рассмотреть.
- Копирование принятых замечаний для вставки в Jira с сохранением форматирования, ссылок и примеров кода.
- Обратная связь для повторного ревью: сохраните комментарий кнопкой «Отправить агенту», и при следующей проверке той же задачи агент учтёт применимые указания.
- Команда `read-feedback`: сохранённую обратную связь по задаче можно прочитать в терминале или передать AI-агенту.
- Отдельная модель OpenCode для каждого проекта Jira: модель для ревью можно выбрать в настройках проекта, сохранив общую модель OpenCode для повседневной работы.

### Изменено

- Обновлено оформление расширения и отчёта: добавлены название RDV AIR и логотип со стрижом.

## [1.2.0] - 2026-10-30

### Добавлено

- Сравнение кода до и после изменений задачи или MR во внешнем приложении. По умолчанию используется KDiff3; также поддерживаются Meld и WinMerge.
- Открытие подготовленного сравнения прямо из расширения Jira.
- Изменения задачи из всех её коммитов собраны в одном сравнении. Полный текст файлов помогает понять, как правки влияют на окружающий код.
- Выбор приложения для сравнения и пути к нему в конфигурации. Для открытия сравнения необходимо установить выбранное приложение; настройка описана в [инструкции](docs/advanced-usage.md#полные-изменения-во-внешнем-diff-инструменте).

## [1.1.1] - 2026-10-07

### Добавлено

- Замечания в Markdown-отчёте получили сквозные номера: теперь на конкретное замечание можно ссылаться по номеру.

### Изменено

- Проект получил название RDV AIR.
- В README подробнее описаны роли «аудитор → критик»: поиск кандидатов и проверка замечаний перед публикацией.
- Добавлено описание MCP и локальных знаний, которые агент использует при ревью.
- Показаны варианты оркестрации: один агент, разделение ролей и параллельные аудиторы.
- Описаны запуск из Jira и работа с Codex, Cursor и OpenCode.
- Добавлен блок «Вопрос-Ответ» по моделям, MCP, передаче кода, запуску ревью и работе с GitLab.

## [1.1.0] - 2026-10-01

### Добавлено

- В README добавлены таблицы поддерживаемых возможностей, схемы работы ревью, пример отчёта и FAQ по моделям, MCP, передаче кода и работе с GitLab.

## [1.0.1] - 2026-09-30

### Изменено

- В Stage 2 описание замечания теперь сначала показывает ошибочный результат, затем его причину. Рекомендация указывает конкретную правку; пример кода добавляется, когда он помогает понять исправление.
- В инструкциях ревью уточнена работа с UTF-8 и PowerShell. При повреждённом отображении русского текста агент повторно читает файл с правильной кодировкой перед анализом.

## [1.0.0] - 2026-09-25

### Добавлено

- Первый публичный релиз `review-tasks` для поэтапного ревью изменений 1С.
- Подготовка отдельного каталога ревью по ключу задачи GitLab или Merge Request. В проверку попадают изменённые модули BSL и тексты запросов в макетах отчётов СКД.
- Запуск Stage 1 и Stage 2 в Codex, Cursor и OpenCode с проверкой результата и созданием Markdown-отчёта.
- Skills `review-setup` и `review-init` для установки, настройки проекта и подготовки каталога задачи.
- Ручной запуск без Jira и внешних MCP-серверов; при необходимости можно подключить MCP для внешнего подтверждения замечаний.
- Запуск ревью со страницы Jira через расширение Chrome и локальный сервис, включая настройки проекта и отдельную инструкцию для задачи.
- Инструкции по установке, настройке Git и MCP, запуску ревью и диагностике ошибок.
